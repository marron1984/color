# 人材マッチングシステム（C-COLLECTION.CO.,LTD.）

飲食店（店舗）の求人ニーズに応じて、登録スタッフ（ホール・キッチン・店長など）を
**AI（スコアリング＋LLM）でピックアップ**する、飲食店特化の人材マッチング管理システムです。

「人材紹介事業 3つの構成要素」を土台に、飲食業界向けに特化しています。

| 構成要素 | このシステムでの対応 |
|---|---|
| **店舗**（新規開拓・既存顧客・求人内容ヒアリング） | 店舗管理・求人票（必須スキル/待遇/職種/勤務形態） |
| **求職者・人材**（募集・プロフィール作成・連絡） | スタッフ登録（スキル・経験・希望待遇・職種・稼働状況） |
| **マッチング業務**（スキル・待遇条件・職種・面接調整・採否・入社フォロー） | AI マッチング（スコアリング＋推薦理由）・進捗ステータス管理 |

対応職種の例: ホール／キッチン／調理長／店長／副店長／バリスタ／寿司職人／パティシエ／ソムリエ など。
国内に加え、海外店舗（シンガポール・NY 等）への紹介、外国籍スタッフ（特定技能 等）の管理にも対応します。

---

## 特長

- 🎯 **AI ピックアップ**: 求人票に対して登録スタッフをスコアリングし、適合度の高い順に候補を提案
- 🌐 **海外人材紹介に対応**: 国籍・対応言語・在留資格・希望勤務国と、求人側の勤務国・必要言語・ビザサポートを管理し、**「対応言語」「勤務国」もマッチング観点に反映**
- 🛂 **ビザ／在留資格の適格性判定**: 国籍×勤務国×職種×経験から、想定ビザ種別・要件・目安期間・スポンサー要否・実現可能性を自動判定し、マッチング結果に表示（日本受入＝特定技能等／海外送出＝E-2・EP・482 等）
- 📈 **採用管理＋アウトカム学習（定着率フィードバック）**: マッチング候補を選考パイプライン（提案→面接→内定→採用）で管理し、採用後の**在籍／離職・在籍日数・離職理由**を記録。実績から「成功した採用に効いた観点」を学習し、マッチングの重みに反映（「学習した重みで評価」）。決定率・定着率・平均在籍日数を可視化
- 🔎 **人材の"検証"レイヤー（信頼性の裏取り）**: 本人確認・職歴・スキル・語学・資格・学歴・ビザ書類・リファレンスの確認状況（未検証/確認中/確認済/相違あり）と証跡を記録。重み付きで**検証スコア（信頼度）**を算出し、人材一覧・マッチング結果に🔎バッジで表示。相違ありは⚠で警告
- 📊 **説明可能なスコア**: スキル・経験 / 対応言語 / 待遇条件 / 勤務国 / 職種 / 勤務形態 / 稼働可否の7観点を内訳表示
- 💡 **推薦理由の自然文生成**: Claude API があれば LLM で推薦理由を生成、無ければスコア明細からテンプレート生成（**API キー無しでも動作**）
- 📄 **履歴書の自動読み込み**: PDF・画像・テキストの履歴書からスタッフ登録フォームを自動入力（国籍・語学・在留資格・希望勤務国も抽出。Claude API があれば PDF/画像も解析）
- 📝 **詳細な登録項目**: 求人（雇用形態・給与詳細・勤務時間・休日・福利厚生・選考フロー 等）／人材（性別・生年月日・現住所・最終学歴・職務経歴・自己PR 等）まで対応
- 📊 **ダッシュボード**: 店舗・稼働可能人材・募集中求人の件数と、職種別／国籍別／勤務国別の内訳をひと目で把握
- 🗂 店舗・人材・求人・マッチングを一元管理する明るい Web UI
- 📱 **スマホ対応**: レスポンシブ設計。スマホでは下部固定ナビ・1カラムフォーム・大きなタップ領域（iOS のズーム防止・セーフエリア対応）
- ✍️ **わかりやすい入力**: スキル・言語・必須要件は、名前を選び習熟度/重要度/レベルを選んで「＋追加」する方式（チップ表示・× で削除）。専門的な記法や書式を覚える必要がありません

## Vercel へのデプロイ

このリポジトリは Vercel のサーバーレス (Python) で動作します。

- `api/index.py` … Vercel 用の ASGI エントリポイント（`app.main:app` を公開）
- `vercel.json` … 全リクエストを関数へルーティング＋静的ファイルを同梱

リポジトリを Vercel に接続すればそのままビルド・デプロイされます。
初回アクセス時にデモデータ（飲食店・海外店舗を含む）が自動投入されます。

### ⚠️ データ永続化について（重要）— 「登録したものが消える」場合

サーバーレス（Vercel）では、既定の SQLite が書き込み可能な `/tmp` に置かれます。
`/tmp` は**インスタンスの再起動（コールドスタート）でリセット**されるため、
**UI で登録したデータは保持されません**。この状態のときは画面上部に警告バーが表示されます。

継続利用するには **外部の永続データベース（Postgres）** を接続してください。
接続すると警告バーは消え、データが永続化されます（ドライバ `psycopg[binary]` は同梱済み）。

#### 設定手順（Vercel Postgres / Neon の例）

1. Vercel のプロジェクト → **Storage** から Postgres（Neon）を作成して接続する。
   - これだけで `POSTGRES_URL` などの環境変数が自動で注入されます。
   - 本アプリは `STAFFING_DATABASE_URL` → `POSTGRES_URL_NON_POOLING` → `POSTGRES_URL` →
     `DATABASE_URL` の順に**自動検出**するため、通常は追加設定なしで認識します。
2. 再デプロイ（または再起動）する。起動時にテーブルが自動作成されます。
3. 画面上部の警告バーが消えていれば永続化 OK。

外部の Neon / Supabase 等を手動で使う場合は、接続文字列を環境変数に設定します
（`postgres://...` 形式でも自動で `postgresql+psycopg://` に変換します）。

```bash
STAFFING_DATABASE_URL="postgres://user:pass@host/dbname?sslmode=require"
```

- デモデータ: **DB が空のときだけ自動投入**します（外部 DB でも。既に登録があれば何もしません）。
  投入したくない場合は環境変数 `SEED_DEMO=0` を設定してください。
- ローカル開発では `./staffing.db` に保存され、再起動しても消えません。
- libSQL/Turso 等でも `STAFFING_DATABASE_URL` を指定すれば利用できます。

## ビザ／在留資格の適格性判定

海外飲食人材紹介の最大の摩擦である「その国で就労できるか」を、国籍×勤務国×職種×経験から
ルールベースで判定します（`app/visa.py`）。

- **日本受入（インバウンド）**: 特定技能1号（外食業）／技能（外国料理の調理師）／技術・人文知識・国際業務／
  ワーキングホリデー／留学（資格外活動）／永住・定住 等
- **海外送出（アウトバウンド）**: シンガポール（EP／S Pass／Work Permit）、米国（E-2／O-1／H-2B／L-1）、
  豪州（WH／TSS 482）ほか。未対応国は「要確認」として提示。
- 各候補について、想定ビザ・**要件・目安期間・スポンサー要否・実現可能性（可能/条件付き/要確認/困難）**を提示。
- マッチング結果カードに自動表示。単体判定は `POST /api/visa/assess`。

> ⚠️ 本判定は一般的な目安です。正式な可否は最新の移民法・運用に基づき、行政書士・移民弁護士等の専門家や当局にご確認ください。

## 採用管理＋アウトカム学習（定着率フィードバック）

「マッチングして終わり」ではなく、**採用後の定着まで**を扱うことで、紹介の質を継続的に高めます（`app/learning.py`）。

- **選考パイプライン**: マッチング結果の「＋採用管理に保存」で候補を登録。ステータスを
  提案 → 面接 → 内定 → 採用 → 不採用 で管理。採用後は**在籍中／離職・在籍日数・離職理由**を記録。
- **アウトカム学習**: 成功採用（採用され離職していない）と失敗（不採用／早期離職）の
  観点スコア差から「成功に効いた観点」の**重要度**を算出。既定重みを
  `重み × (1 + α×重要度)` で補正し、**信頼度（実績件数 / N_REF）**で既定重みとブレンド。
  データが少ないうちは既定重視、増えるほど学習重みへ寄せます（学習データ不要の統計的アプローチ）。
- **反映**: マッチング画面の「学習した重みで評価」をオンにすると、学習した重みで再ランキング（`use_learned`）。
- **可視化**: 決定率＝採用/(採用+不採用)、定着率＝在籍/(在籍+離職)、平均在籍日数、観点別の寄与度バーを「採用管理」タブに表示。
- API: `GET /api/matches`・`POST /api/matches`・`PATCH /api/matches/{id}`・`DELETE /api/matches/{id}`・`GET /api/learning`。

## 人材の"検証"レイヤー（信頼性の裏取り）

海外飲食人材紹介で受入店舗が最も不安に感じる「**経歴・スキルは本物か**」に応えるため、
登録内容の裏取り状況を証跡付きで管理します（`app/verification.py`）。

- **検証カテゴリ（重み）**: 本人確認(3) / 職歴・前職照会(3) / スキル・実技(3) / 語学レベル(2) /
  資格・免許(2) / ビザ・在留書類(2) / 学歴(1) / 推薦・リファレンス(1)。
- **状態**: 未検証 / 確認中 / 確認済 / **相違あり**。確認方法（書類・面談・実技テスト・前職照会・第三者機関）と
  証跡（URL・書類名・メモ）・確認担当者・確認日時を記録。
- **検証スコア（信頼度）**: カテゴリ別の最良ステータス × 重みの達成率（0-100）。
  確認済=満点・確認中=部分点・相違/未検証=0点。スコアに応じて 未検証／基本確認／標準確認／確認充実 のレベルを表示。
- **表示**: 人材一覧とマッチング結果に「🔎 検証 スコア・レベル」バッジを表示。相違ありは⚠で警告。
  人材カードの「検証」からモーダルで項目を追加・更新・削除。
- API: `GET /api/verifications/meta`・`GET/POST /api/talents/{id}/verifications`・
  `PATCH /api/verifications/{id}`・`DELETE /api/verifications/{id}`。

## 登録項目（詳細）

求人・人材の登録では、実務で必要な詳細項目まで入力できます（長い項目は「詳細（追記事項）」として折りたたみ表示）。

- **求人**: 雇用形態／給与詳細（固定残業・試用期間・昇給・賞与・手当）／勤務時間（シフト・休憩・残業・夜勤）／
  休日・休暇／応募資格／福利厚生／求める人物像／選考フロー／その他（客単価・席数・スタッフ構成・独立実績・海外支援 など）
- **人材**: 性別／生年月日／現住所／希望業態／雇用形態／転居可否／最終学歴／保有資格／職務経歴／海外勤務経験／自己PR／将来の目標
- 業態・職種は候補（datalist）から選択できます（和食・寿司・イタリアン…／料理長・寿司職人・ホール…）。

## 使い方

1. **店舗**タブで店舗（クライアント）を登録
2. **人材**タブでスタッフを登録
   - スキル・対応言語・希望勤務国は、名前を選んで習熟度／レベルを選び「＋追加」で登録（チップ表示・× で削除）。テキストの書式を覚える必要はありません。
   - 「📄 履歴書から自動入力」で履歴書（PDF/画像/テキスト）を読み込むと、フォームが自動入力されます。内容を確認・修正してから登録してください。
3. **求人**タブで求人票を登録
   - 必須スキルは「スキル名＋重要度（高/中/低）＋最低レベル」、必要言語は「言語＋最低レベル」を選んで「＋追加」。
4. **マッチング**タブで求人を選び「ピックアップ実行」→ 適合度順に候補が表示されます
   - 求人カードの「🎯 この求人でマッチング」からワンクリックで実行することもできます。

各カードの「編集」ボタンで登録済みの店舗・人材・求人を修正できます（フォームが編集モードになり「更新」で保存、「キャンセル」で中止）。

## マッチングの仕組み（大手求人サービスのノウハウを集約）

`app/matching.py` は、Indeed・リクルート・LinkedIn 等で実際に使われる確立した
手法を、学習データ不要の決定論アルゴリズムとして実装しています。

### ① 双方向レコメンド（reciprocal recommendation）

求人マッチングは両面市場です。総合スコアは 2 つの適合度の**幾何平均**で算出します。

```
総合 = (企業ニーズ適合)^0.6 × (本人希望適合)^0.4
```

- **企業ニーズ適合（企業→人材）**: スキル要件・対応言語・職務内容マッチ・経験練度・職種
- **本人希望適合（人材→企業）**: 待遇・勤務地/国・勤務形態・稼働可否

片側だけ高くても総合は伸びません。例: スキル完璧でも提示待遇が本人の希望を大きく下回る求人は、
「本人が敬遠しやすい＝成立しにくい」ため総合が下がります（画面に両側のスコアを表示）。

### ② BM25 テキスト関連度（Indeed 流の職務内容マッチ）

求人の職務内容（タイトル・説明・必須スキル）と人材プロフィールの文章一致を **BM25** で評価。
日本語は形態素解析なしで動くよう**文字 bi-gram**をトークンにし、候補集団内で相対評価します。

### ③ その他のノウハウ

| 手法 | 内容 |
|---|---|
| スキル・タクソノミー展開 | 近縁スキルを割り引いて部分評価（例: 必須「仕込み」に「調理」保持者を加点。`SKILL_FAMILIES`） |
| 習熟度の差別化 | 最低レベル超過分を加点し Lv5 と Lv3 を区別 |
| 必須要件ゲート | 重要度「高」の必須スキル欠落は総合を強く減点（`MUST_HAVE_GATE`） |
| 経験・練度フィット | 求人の要求練度に対し、経験不足も過剰資格も減点 |
| 待遇バンド整合 | 提示待遇と本人希望の整合（通貨が JPY 以外は参考値） |
| スコア較正 | 候補集団内の相対順位（percentile）を付与し「候補内 上位◯%」を表示 |

> 各係数・スキル群・職種群は `app/matching.py`（`EMP_WEIGHTS` / `CAND_WEIGHTS` /
> `SKILL_FAMILIES` / `ROLE_FAMILIES` など）で調整できます。稼働不可の人材は候補から除外されます。
> さらに高度化するなら、Claude API による意味的リランキングや、
> クリック/採用ログを用いた learning-to-rank への発展も可能です。

### 海外人材紹介向けの項目

- **スタッフ**: 国籍 / 対応言語（言語＋レベル） / 在留資格・就労資格（特定技能 等） / 希望勤務国・地域
- **求人**: 勤務国・地域 / 必要言語（言語＋最低レベル） / ビザサポート有無 / 通貨

### 連絡先の扱い

- スタッフは連絡先（電話 / メール / その他連絡手段：LINE・WeChat・WhatsApp 等）を**人材情報として保有**します。
- プライバシー配慮のため、**人材一覧には既定で表示しません**。各カードの「連絡先」ボタンを押したときだけ展開表示されます。
- **マッチング結果の候補カードからも個人情報にアクセスできます**。「個人情報・連絡先を表示」ボタンで、フリガナ・希望年収・希望勤務地・在留資格・希望勤務国・連絡先（電話/メール/その他）・プロフィールを開閉表示します（既定は非表示）。
- 履歴書の自動読み込みでは、電話番号・メール・メッセージアプリ ID も抽出してフォームに反映します。
- 通貨が JPY 以外の海外求人は、希望年収（万円）との単純比較ができないため待遇スコアを参考値（0.85）として扱います。正確に評価したい場合は円換算額を入力してください。

| POST | `/api/visa/assess` | **ビザ適格性判定**（国籍×勤務国×職種×経験 等） |
| POST | `/api/talents/parse-resume` | **履歴書アップロード**→フォーム下書きを返す（保存はしない） |
| GET | `/api/jobs/{id}/matches` | 求人ごとの保存済みマッチング一覧 |
| GET | `/api/matches` | 保存済みマッチング（採用管理）一覧 |
| POST | `/api/matches` | 候補を採用管理に保存（`job_id` / `talent_id`、重複は無視） |
| PATCH | `/api/matches/{id}` | ステータス・定着（在籍/離職）・在籍日数・離職理由を更新 |
| DELETE | `/api/matches/{id}` | 採用管理から削除 |
| GET | `/api/learning` | **アウトカム学習**（集計指標＋学習した観点別重要度・重み） |
| GET | `/api/verifications/meta` | 検証項目の選択肢（カテゴリ・ステータス・方法） |
| GET/POST | `/api/talents/{id}/verifications` | **検証項目**の一覧（検証スコア付き）・追加 |
| PATCH/DELETE | `/api/verifications/{id}` | 検証項目の更新（状態変更で確認日時を自動記録）・削除 |

対話的な API ドキュメントは起動後 `/docs`（Swagger UI）で確認できます。
