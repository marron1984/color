# 人材紹介マッチングシステム

企業（クライアント）の求人ニーズに応じて、登録人材（職人・スタッフなど）を
**AI（スコアリング＋LLM）でピックアップ**する人材紹介・派遣向けの管理システムです。

配布資料「人材紹介事業 3つの構成要素」を土台に設計しています。

| 構成要素 | このシステムでの対応 |
|---|---|
| **クライアント**（新規開拓・既存顧客・求人内容ヒアリング） | クライアント管理・求人票（必須スキル/待遇/タイプ/勤務形態） |
| **求職者・人材**（募集・プロフィール作成・連絡） | 人材登録（スキル・経験・希望待遇・タイプ・稼働状況） |
| **マッチング業務**（スペックスキル・待遇条件・タイプ(OS)・面接調整・採否・入社フォロー） | AI マッチング（スコアリング＋推薦理由）・進捗ステータス管理 |

---

## 特長

- 🎯 **AI ピックアップ**: 求人票に対して登録人材をスコアリングし、適合度の高い順に候補を提案
- 📊 **説明可能なスコア**: スペックスキル / 待遇条件 / タイプ(OS) / 勤務形態 / 所在地 / 稼働可否の6観点を内訳表示
- 💡 **推薦理由の自然文生成**: Claude API があれば LLM で推薦理由を生成、無ければスコア明細からテンプレート生成（**API キー無しでも動作**）
- 🗂 クライアント・人材・求人・マッチングを一元管理する Web UI

## 技術スタック

- バックエンド: **FastAPI** + **SQLAlchemy 2.0** + **SQLite**
- フロントエンド: バニラ HTML/CSS/JS（依存ライブラリなし・単一ページ）
- AI 連携: **Claude API**（任意）／ 決定論的スコアリングエンジン（必須）

## セットアップ

```bash
# 依存インストール
pip install -r requirements.txt

# デモデータ投入（建設・製造・飲食：クライアント6・人材13・求人6）
python -m app.seed

# 起動
uvicorn app.main:app --reload
# → http://127.0.0.1:8000 をブラウザで開く
```

### Claude API 連携（任意）

環境変数を設定すると、推薦理由が LLM 生成に切り替わります（未設定でもスコアリングで動作）。

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
export ANTHROPIC_MODEL="claude-sonnet-5"   # 省略可
```

UI 右上のバッジで連携状態（`Claude 連携 ON` / `スコアリングのみ`）を確認できます。

## Vercel へのデプロイ

このリポジトリは Vercel のサーバーレス (Python) で動作します。

- `api/index.py` … Vercel 用の ASGI エントリポイント（`app.main:app` を公開）
- `vercel.json` … 全リクエストを関数へルーティング＋静的ファイルを同梱

リポジトリを Vercel に接続すればそのままビルド・デプロイされます。
初回アクセス時にデモデータ（建設・製造・飲食）が自動投入されます。

### ⚠️ データ永続化について（重要）

サーバーレスではファイルシステムが読み取り専用のため、SQLite は書き込み可能な
`/tmp` に置いています。`/tmp` は**インスタンスが再起動（コールドスタート）すると
リセット**されるため、UI で登録したデータは永続しません（デモ用途向け）。

**業務で継続利用（社内管理システム）する場合は、外部の永続 DB を推奨します。**
`STAFFING_DATABASE_URL` を設定すれば SQLite 以外の DB に切り替えられます。

```bash
# 例: Vercel Postgres / Neon などの接続文字列を環境変数に設定
STAFFING_DATABASE_URL="postgresql+psycopg://user:pass@host/dbname"
```

> Postgres 等を使う場合は対応ドライバ（例: `psycopg[binary]`）を
> `requirements.txt` に追加してください。libSQL/Turso での永続化にも対応可能です。

## 使い方

1. **クライアント**タブで企業を登録
2. **人材**タブで職人・スタッフを登録（スキルは「名称,レベル」を1行1件）
3. **求人**タブで求人票を登録（必須スキルは「名称,重み,最低レベル」を1行1件）
4. **マッチング**タブで求人を選び「ピックアップ実行」→ 適合度順に候補が表示されます

## マッチングの仕組み

`app/matching.py` の決定論的スコアリングエンジンが各観点を 0–100 で評価し、
重み付き合計で総合適合度を算出します。

| 観点 | 重み | 評価内容 |
|---|---|---|
| スペックスキル | 0.40 | 必須スキルのカバー率＋レベル充足度（重み付き） |
| 待遇条件 | 0.20 | 提示年収が希望年収を満たすか |
| タイプ(OS) | 0.15 | 人物タイプ・適性の一致 |
| 勤務形態 | 0.10 | 実地／オンラインの適合 |
| 所在地 | 0.10 | 勤務地の一致（オンライン勤務は不問） |
| 稼働可否 | 0.05 | 即稼働可 / 稼働中 / 稼働不可 |

> 重みは `app/matching.py` の `WEIGHTS` で調整できます。稼働不可の人材は候補から除外されます。

## API

| メソッド | パス | 説明 |
|---|---|---|
| GET | `/api/health` | 稼働状態・LLM 連携有無 |
| GET/POST/DELETE | `/api/clients` | クライアント管理 |
| GET/POST/DELETE | `/api/talents` | 人材管理 |
| GET/POST/DELETE | `/api/jobs` | 求人管理 |
| POST | `/api/jobs/{id}/match` | **AI マッチング実行**（`top_n` / `use_llm` / `persist`） |
| GET | `/api/jobs/{id}/matches` | 保存済みマッチング一覧 |
| PATCH | `/api/matches/{id}` | 進捗ステータス更新（proposed→interview→offer→hired/rejected） |

対話的な API ドキュメントは起動後 `/docs`（Swagger UI）で確認できます。


## プロジェクト構成

```
api/
  index.py      Vercel サーバーレス用エントリポイント
app/
  main.py       FastAPI アプリ・REST エンドポイント・静的配信
  models.py     ORM モデル（Client / Talent / Job / Match）
  schemas.py    Pydantic 入出力スキーマ
  matching.py   スコアリング・マッチングエンジン
  ai.py         Claude API 推薦理由レイヤー（フォールバック付き）
  seed.py       デモデータ投入（建設・製造・飲食）
  database.py   DB 接続（サーバーレスでは /tmp、STAFFING_DATABASE_URL で上書き可）
  static/       Web UI（index.html / app.js / styles.css）
tests/
  test_matching.py  マッチングエンジンのテスト
vercel.json     Vercel デプロイ設定
```
